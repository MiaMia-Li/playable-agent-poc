# 构建加速与计时

## 文件传输

Skill 文件按确认的玩法筛选后，使用 gzip 包一次上传，在 sandbox 中解包。
未选中的独立 HTML 模板不传输。Harness 只注册文字指令，不再重复携带 HTML 和素材。
最终完整性检查在 sandbox 内执行一次，使用宿主保留的 SHA-256 清单；取消信号贯穿上传与校验。
用户素材和本轮确认配置仍独立注入，不进入公共浏览器快照。

## 阶段记录

应用将阶段开始时间和结束耗时存为结构化构建事件。前端每秒更新运行中的计时，
结束后累计同一阶段的所有区间，刷新后可从事件恢复。旧构建没有阶段记录时不补造数据。

| 阶段 | 边界 |
| --- | --- |
| 环境准备 | 准备配置、素材、创建 sandbox 和校验预装工具 |
| 文件传输 | 构建文件注入、解包与基线准备 |
| 模型修改 | Agent 执行，扣除已识别的浏览器验收命令区间 |
| 浏览器验收 | 固定 `node …/browser-acceptance.mjs` 命令的开始与结束 |
| 产物检查 | 平台结构校验、敏感信息检查及主文件哈希检查 |
| 产物发布 | 写入产物存储并提交发布状态 |

浏览器阶段包括启动、场景执行、截图与证据写入。只有按标准入口运行才单独计时；
其他临时调试命令仍归入 Agent 时间，页面用“未记录”区分未观测和零耗时。
固定入口收集通用证据，玩法断言仍由本次场景脚本实现，不能仅凭通用加载检查宣布玩法通过。

## Skill 分拆

四个独立模板分别使用 `dragon-slots-playable`、`dragon-reward-wheel-playable`、
`zeus-scatter-playable`、`balloon-master-playable`；不匹配模板的玩法使用 `freeform-playable`。
麻将四种配对模式保留 `mahjong-pair-match-playable`。

每个入口均有独立 SKILL.md，应用根据确认后的 sourceTemplateId 优先选择，
不会因旧 mode 字段而误用麻将 Skill。模板 HTML 和专属 reference 已迁入各自 Skill。麻将构建器、运行时和默认素材仅保留在麻将 Skill 中。
通用浏览器验收、自由玩法结构检查和独立模板适配规范集中存放在 `skills/_shared/`，
本地 CLI、Harness 指令加载和云端上传均使用同一归属映射。构建时合并所选 Skill 与公共依赖，
维持原有工作区相对路径；不会上传其他模板，也不会复制多份公共工具。历史 Plugin 标识保持兼容。

本次无需重建浏览器快照：新验收脚本随工作区上传。部署应用代码后，对新构建生效。

## 五分钟预览与完整验收

8 个注册模板（四种麻将模式、龙主题老虎机、龙主题转盘、宙斯消除、气球玩法）统一接入两阶段流程，远程 Harness 和本地 CLI 均适用。

1. 环境与传输完成后，模型优先完成可玩预览；从 sandbox 流程开始计算的预览目标为 5 分钟，并为基础交互检查及存储预留时间。
2. 基础浏览器场景必须执行真实输入并检查效果。通过响应式、离线与敏感内容检查后，单独保存 preview.html 并即时展示。
3. 同一个后台构建任务继续完整验收，要求全量报告通过且 SHA-256 匹配最终 HTML，再执行平台检查并发布正式产物。模型最多一次修复为提示约束；应用不再为模型阶段设置自动取消时限。
4. 界面显示“预览已就绪，完整验收中”；验收失败保留预览并显示失败状态。预览不能从下载入口交付，也不覆盖上次正式版本。

五分钟是可体验预览的目标，不是完整交付保证。素材生成、冷启动、队列和网络等待仍可能使端到端请求超时；超出 5 分钟目标时界面提示继续生成，不中断当前修改；预览实现和完整验收模型阶段均不设置硬超时，用户取消仍立即生效。Sandbox 生命周期、部署平台限制和单个浏览器操作的超时仍独立生效。非模板自由玩法继续原流程。

## 参数修改快路

新生成产物把标题、CTA、免责声明、语言与商店地址放入 `playable-campaign-config` JSON，并绑定到原引擎。
只有完整验收确认绑定有效的产物才能保留 `playable-campaign-binding-v1` 标记。
确认方案中只有这些参数改变、修改计划明确 parameterOnly、且正式基线存在绑定和已保存的两种场景时，宿主直接更新 JSON，跳过模型实现并复用浏览器场景。完整场景失败时再交给模型处理。

老版本或不支持实际字段绑定的产物会自动退回模型修改。不会为凑齐参数接口添加覆盖原游戏的假文案层。
场景随正式产物存为 scenarios.json；预览独立保存，刷新页面通过事件恢复，不增加数据库迁移。
