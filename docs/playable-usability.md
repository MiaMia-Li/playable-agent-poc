# Playable Studio 交互增强

## 构建期间追加需求

构建和验收期间保留输入框，发送按钮变为「加入排队需求」。文字、附件和用户选择的基准版本一起保存；附件先通过现有上传接口保存，队列只记录附件 ID。

队列可以逐条编辑、撤回。当前任务处于可接收需求的阶段时，按顺序通过现有 messages 接口发送；仍需用户确认 Confirmation Proposal 才会触发下一次构建。构建失败或需求发送失败时，保留队列供用户检查、重试或撤回。发送未完成便刷新页面时不会静默重发，以免重复调用模型。

队列存储在当前标签页的 sessionStorage 中，可以恢复刷新和站内跳转；自动发送需要打开对应任务。关闭标签页或换设备不保证恢复。存储不可用时界面提示保持页面打开。

## 完成提醒

浏览过的正在构建任务会登记到全局监听器，切换到站内其他页面后仍会查询状态。完成或失败时显示带「打开任务」入口的站内提醒。用户可主动开启浏览器通知；仅在页面处于后台且通知权限已授予时发送系统通知。

监听记录在当前标签页保存，不对共享空间里的所有任务主动发通知；关闭整个标签页后不继续后台监听。

## Preview 框选反馈

已保存的版本在 Preview 工具栏提供「框选画面提出修改」。点击捕获当前画面，在静止画面中拖动框选或选择整张画面，输入修改要求后加入需求草稿。草稿带上截图附件、截图时的版本、归一化区域和用户要求；基准版本通过现有 baseBuildId 参数交由服务端验证。

反馈表达的是修改意图，进入 Requirement Brief；不写入 Gameplay Annotation，也不自动将截图绑定为生产素材。用户检查后再发送，构建期间发送则进入队列。

截图脚本只注入显式带 feedback=1 的编辑预览，下载的 HTML 保持原样。预览保持 opaque-origin sandbox 和禁止外部网络连接的 CSP。父页面只接受来自当前 iframe、匹配当前请求 ID 的有界 PNG 消息。WebGL 仅在编辑预览中保留绘图缓冲。截图是对当前 DOM/Canvas 的渲染；特殊字体或浏览器不支持的效果可能有差异，失败时可改用上传截图。
