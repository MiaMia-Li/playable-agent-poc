# Gameplay Blueprint 将模型推论与用户标注分层保存

一份 Gameplay Blueprint 并列携带模型推论和用户的 Gameplay Annotation，附一句明确声明用户标注优先，而不是把标注合并进它所修正的那条推论。合并需要每条 inference 有稳定 id，还需要抽取时可靠地指对目标，而指错目标会静默出错；并列的最坏情况只是多给一条正确信息。两个消费端本来就是整包 JSON 接收 Blueprint，因此顶层 `annotations` 数组能零管线改动地到达需求 Agent 和构建 Sandbox。

## 后果

- 用户标注永远不会触发重新分析。重跑是用户显式发起的独立动作，标注以「请重点查证这几段」而非既定事实的形式喂入，模型仍有权反驳——分歧是值得呈现的信号，不是错误。（该重跑即 Verification Pass，因网关不支持区间裁剪而暂缓，见 spec §7.5。分层本身不受影响，且因为首轮只能拿到 1 fps，标注层反而成为亚秒级动作进入 Blueprint 的唯一通道。）
- 标注绑定参考视频的 asset id，因此重新分析同一支视频只替换模型层，标注层在未变的时间轴上依然有效。
- 构建 Agent 仍有可能在并列的两个说法里采信模型那条。此风险暂时接受，升级路径是 per-inference id 加精准覆写。
