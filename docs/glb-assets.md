# 通用 GLB 素材支持

GLB 是独立的 3D 资源类型，适用于角色、道具、载具、场景、展示对象等，不绑定任何玩法或模板。新上传模型进入 `models` 分类（界面显示「3D 模型」），不归为牌面，不进入参考图片分析。旧任务中保存在其他槽位的模型仍然可用。

## 使用流程

1. 首页、对话附件或 Confirmation Proposal 的「3D 模型」中上传 GLB。
2. 按文件名说明用途，以及动画、摆放和交互需求。模型角色由需求决定，系统不根据文件格式推断碰撞方式。
3. 点击「预览 3D」旋转和缩放；带动画的模型可选择片段并播放、暂停，或切回默认姿态。
4. Requirement Brief 可以记录是否使用模型。Confirmation Proposal 使用 `resources.models` 记录素材策略和用途；旧方案未包含该字段时保持兼容，视为没有额外模型。
5. 构建 Agent 收到原始模型、材质、UV、节点层级、骨骼、形态目标及动画数据，并在素材清单中看到网格数量、动画名称等信息。Agent 按实际数据和用途集成，不预设形状、尺寸、朝向或动画名称。
6. 当前自定义三维构建使用 Three.js；展示或预制动画可不使用物理引擎。需要真实物理交互时才配置 Rapier 和适合的碰撞体。若当前模板不兼容，需要先更新构建方案。
7. GLB 和贴图内嵌到交付 HTML，继续接受既有离线、画面和交互验证。模型上传不自动等于动作绑定或物理逻辑已经完成。

## 当前格式范围

- 自包含 GLB 2.0，单个文件最多 4 MiB。每个槽位最多 8 个文件，任务最多 30 个文件。
- 一个内嵌二进制缓冲区，PNG/JPEG/WebP 贴图；支持场景层级、骨骼、形态目标和动画数据的原样传递。
- 暂不接受外置贴图/缓冲区、Draco、Meshopt、KTX2/Basis 和稀疏访问器。这些是当前加载器的格式范围限制，与玩法无关。
- 最终 HTML 仍受已确认的投放标准约束；Base64、模型、纹理和引擎代码一起计入体积。
- 本地 demo 使用确定性示例 Agent，不承担通用 3D 内容生成；实际模型集成由生产或本地 Codex 构建 Agent 完成。

## 实现与兼容

上传沿用私有 Blob 和素材表；槽位为文本字段，无需数据库迁移。multipart 在保存前检查字节，直接上传在完成时检查实际字节，失败会删除 Blob。

`glb.mjs` 是上传、预览与离线构建共用的格式检查器；它限定产品支持范围，不替代完整 Khronos glTF 验证器。云端和本地 CLI 共用模型清单生成逻辑。`asset-manifest.json` 的 `sources[].treatment` 保留用途说明，`assets[].model` 提供结构及动画元数据。

Three.js 0.165.0 预览按需加载；通过父级节点居中，保留模型自身根节点变换及动画。构建 Agent 使用模型真实的动画名称，骨骼实例需要 SkeletonUtils.clone，避免共享骨骼状态。是否播放动画、如何映射交互和是否使用物理，由确认需求决定。
