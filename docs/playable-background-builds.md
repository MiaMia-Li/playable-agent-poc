# 试玩构建执行时长（PoC）

## 问题与修复

确认接口通过 Next.js 的 `after()` 执行生成、验证和发布。虽然接口先返回 `202`，回调仍受 Vercel 应用函数执行时长限制。此前函数在 300 秒后超时，Sandbox 中的 Agent 可能继续生成，但应用已无法接收和发布产物。

当前 PoC 保留原执行流程，在 `app/api/playable-tasks/[taskId]/confirm/route.ts` 导出 `maxDuration = 1800`，将该接口的执行预算提高到 30 分钟。`lib/playable/sandbox-runner.ts` 同时把 Agent Sandbox 的期限设为 30 分钟，避免其默认期限提前结束生成。

不再使用独立编排 Sandbox、后台运行包或工作进程领取字段，本次修复不需要新增数据库迁移。

## 部署条件

- Vercel 项目需要属于 Pro 或 Enterprise 团队，并启用 Fluid Compute。
- 超过 800 秒的执行时长属于 Beta，需要通过 `maxDuration` 显式启用；Hobby 不支持该 30 分钟配置。
- 使用现有的 `pnpm build` 构建并重新部署。确认部署后的确认接口执行期限为 1800 秒。
- `vercel.json` 中 `app/api/tasks/route.ts` 的 300 秒配置属于另一个接口，无需修改。

依据：[Vercel 官方于 2026 年 6 月 15 日发布的 30 分钟函数支持公告](https://vercel.com/changelog/vercel-functions-can-now-run-up-to-30-minutes)。

## 保留的进度与保护

确认接口返回后，`after()` 继续执行构建。已有心跳、防并发构建和构建编号校验保持有效；旧结果不能覆盖新构建。

Agent 执行记录沿用左侧对话的 Thinking 样式，构建时展开，结束后收起为耗时与状态摘要。同一工具调用的开始和结束合并成一行，思考摘要及参数、结果按需展开，Agent 说明直接显示，不再使用独立日志卡片。Codex Harness 和 CLI 都记录公开的思考摘要、Agent 说明、工具开始与结束、命令参数和执行结果。标题保持中文固定文案，详情由服务端脱敏后保存，前端每两秒读取事件，刷新后可以恢复展示。最终以验证、上传后的数据库状态和已发布产物判断成功。

公开文本按完整段落上报，工具调用即时上报，不逐 token 写数据库。模型或桥接层没有提供的事件无法补出；隐藏思维链与原始模型载荷不会展示。每个详情字段最多展示 24000 个字符，过长内容有截断提示。参数与结果默认折叠，展开后按纯文本显示，不能执行其中的 HTML 或脚本。

密钥过滤发生在持久化之前，包括本轮 API 密钥、服务端敏感环境变量及常见认证头、密钥和连接串。历史构建只保存过固定文案，不能补回旧工具详情；重新部署后发起的新构建才会包含完整公开事件。

## 使用限制与验证

30 分钟是整个函数的预算，包含准备、Agent 执行、验证和上传，并非 Agent 独享 30 分钟。接近预算上限时仍可能来不及发布，应让实际生成耗时留出余量。

本方案不支持崩溃恢复或无限运行。超过 30 分钟仍会被平台终止，长期没有心跳的任务会由现有回收逻辑标记失败，需要重新发起构建。

部署后发起一个超过五分钟的真实任务，检查确认接口已返回、心跳和步骤持续更新，并最终成功发布产物。仅通过本地构建不能证明线上套餐与 Fluid Compute 配置已经满足要求。

## Thinking 历史保留

每次对话使用独立消息标识；同一轮中的累计摘要更新当前段落，工具后产生的新摘要追加保存，最终回复不覆盖先前摘要。成功保存的回复包含整轮公开摘要，刷新后可以恢复。历次构建分别保留为可展开的记录，新构建不会替换旧构建的 Thinking。已经被旧版本覆盖且未保存的文本无法补回。

构建记录按开始时间归属于此前最近一条生成或修改方案，显示在该消息下面。同一方案的重试仍留在原位置；缺少可靠时间的记录保留在底部兜底区域，避免错配。
