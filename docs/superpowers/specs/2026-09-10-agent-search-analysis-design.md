# Agent 搜索分析功能设计

> 日期：2026-09-10  
> 状态：已完成讨论，待书面评审

## 1. 背景与目标

当前 Playable Studio 的需求 Agent 会识别用户意图、维护 Requirement Brief、选择实现路线，并在用户确认后进入现有构建流程。本功能在需求整理前增加一个可选的竞品研究阶段：

1. 需求 Agent 判断搜索是否有价值。
2. Search Analysis Agent 检索并分析同品类试玩广告创意。
3. 系统向用户展示行业总结和 3–5 个候选案例。
4. 用户选择一个主参考，并可附加其他案例的局部亮点。
5. 需求 Agent 将用户选择转换为 Requirement Brief，继续现有确认和构建流程。

搜索不是每轮对话的固定前置步骤，也不能直接触发构建。第一版目标是利用公开证据提供“热门、高频出现或趋势明显”的参考，并为以后接入内部投放指标和第三方广告情报数据预留统一接口。

## 2. 范围

### 2.1 MVP 范围

- 需求 Agent 按意图决定直接搜索、建议搜索或跳过搜索。
- 检索少量明确允许访问的公开广告库、榜单和案例内容。
- 纳入 Playable 录屏、广告视频和案例拆解，但候选必须能够观察出交互玩法。
- 在 30–60 秒内流式展示真实进度，返回 3–5 个可靠候选。
- 输出行业玩法总结、候选分析、来源和证据等级。
- 在对话流中完成候选展示和选择。
- 支持一个主参考、多个附加亮点、调整要求和明确排除项。
- 保存研究任务、候选分析和用户最终选择。

### 2.2 非目标

- 不声称仅凭公开数据能够证明广告具有高 CTR、CVR 或 ROAS。
- 不抓取或复制原始广告实现、品牌素材、商标、原文案或受保护视觉资产。
- 不建设完整的多 Agent 平台、通用爬虫平台或独立研究工作台。
- 不改变构建 Agent、Confirmation 或现有构建状态机的职责。
- 不在第一版同时接入内部投放数据和第三方付费数据源。

## 3. 总体架构

```text
用户输入
   │
   ▼
需求 Agent：判断对话意图
   │
   ├─ 闲聊/帮助 ──────────────→ 普通回复
   ├─ 修改已有试玩 ───────────→ 当前 Revision 流程
   ├─ 需求明确/已有强参考 ─────→ 当前需求整理流程
   └─ 适合竞品研究
          │
          ├─ 用户明确要求搜索 ─→ 直接开始
          └─ Agent 主动建议 ───→ 用户确认后开始
                                   │
                                   ▼
                           Search Analysis Agent
                                   │
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
          检索公开来源          去重与证据评级        玩法结构化分析
              └────────────────────┼────────────────────┘
                                   ▼
                         行业总结 + 3–5 个候选
                                   │
                                   ▼
                     用户选择主参考 + 附加亮点
                                   │
                                   ▼
                    需求 Agent 更新 Requirement Brief
                                   │
                                   ▼
                       当前确认、构建和 Revision 流程
```

### 3.1 职责边界

- **需求 Agent**：识别意图、决定是否建议搜索、与用户沟通，并在用户采用研究方向后更新 Requirement Brief。
- **Search Analysis Agent**：检索、标准化、去重、证据评级和玩法分析；不修改 Requirement Brief，不选择最终需求，不触发构建。
- **用户**：决定是否接受 Agent 主动建议的搜索，并最终选择采用哪些参考。
- **构建 Agent**：保持现有职责，只消费用户确认后的结构化配置。

Search Analysis Agent 是边界独立、输入输出结构化的领域模块。MVP 不需要引入完整的多 Agent 运行平台。

## 4. 触发规则

需求 Agent 必须依据完整对话和当前任务状态判断，不得仅按关键词分类。

### 4.1 直接搜索

- 用户明确要求寻找竞品、热门玩法、市场参考或同类广告。
- 用户明确指定品类、市场、来源或关注点并要求调研。

### 4.2 建议搜索并等待确认

- 用户只提供宽泛方向，例如希望制作“现在流行的消除试玩”。
- 现有模板只能近似匹配，或可能需要自由生成。
- 用户不知道应该选择什么玩法，希望参考市场案例。
- 用户要求数据或市场依据，但未提供明确案例。

建议消息应说明搜索目的和预计用时。用户可以一键选择“开始搜索”或“跳过搜索”。

### 4.3 默认跳过

- 用户已经清楚描述核心循环和交互规则。
- 用户上传了明确参考视频并希望按其内容分析。
- 用户正在修改已有试玩。
- 对话属于闲聊、帮助或其他非游戏需求。
- 当前对话已有同品类、地区、平台和时间范围的有效研究结果，且需求类别没有改变。

用户更改核心玩法类别后，旧结果继续保留，但标记为可能不再相关。

## 5. 搜索状态

搜索状态独立于主任务 `phase`。研究期间主任务继续保持 `draft`，避免破坏现有构建状态机。

```text
suggested → confirmed → searching → analyzing → completed
                                      ├→ failed
                                      └→ cancelled
```

同一个任务可以包含多次 Research Run。用户取消或搜索失败后仍可直接继续现有需求流程。

## 6. 输入与输出契约

### 6.1 Search Brief

需求 Agent向 Search Analysis Agent 提供结构化 Search Brief：

- 游戏品类与子品类。
- 核心玩法关键词。
- 目标地区、语言和广告平台。
- 搜索时间范围。
- 用户特别关注点。
- 当前 Requirement Brief 的必要摘要。

Search Brief 只包含研究所需字段，不传递无关对话和敏感信息。

### 6.2 行业总结

Search Analysis Agent 输出：

- 常见核心循环。
- 高频前三秒钩子。
- 操作方式与单局节奏。
- 成功、失败和奖励反馈。
- CTA 与结束卡模式。
- 当前趋势和对应证据强度。
- 同质化风险和差异化机会。

### 6.3 候选案例

每次返回 3–5 个候选；可靠候选不足时可以少于 3 个，不使用低质量内容凑数。每个候选包含：

- 案例名称、来源链接和抓取时间。
- 可用的预览信息。
- 品类标签、适用地区和时间范围。
- 核心循环、操作方式和关键状态变化。
- 前三秒钩子、反馈方式和 CTA 设计。
- 值得借鉴的玩法亮点。
- 不建议复制的品牌、素材或文案。
- 指标类型、指标值或趋势描述。
- 证据强度和分析置信度。

### 6.4 指标分层

- **公开趋势**：曝光频率、榜单位置、重复投放和发布时间等可公开观察的信号。
- **内部表现**：CTR、CVR、IPM 和 ROAS 等来自自有投放系统的真实指标。
- **第三方估算**：广告情报平台提供的热度或表现估算。

三类指标必须分别标记。没有内部表现数据时，只能描述为“公开热门、高频出现或趋势明显”，不能称为“高转化”或“效果好”。不同指标类型不能在缺少显式归一化和权重说明时直接混合排序。

### 6.5 Reference Selection

用户最终选择独立保存为 Reference Selection：

- 一个主参考。
- 来自其他候选的零个或多个局部亮点。
- 用户自己的调整要求。
- 明确排除的机制、品牌、素材、视觉或文案。

只有用户点击“采用此方向”后，Reference Selection 才能进入需求 Agent。原始研究结果不能自动成为 Requirement Brief 的要求。

## 7. Search Agent 内部组件

```text
Search Orchestrator
   │
   ├─ Source Registry
   │    └─ 管理允许访问的来源、能力和使用限制
   ├─ Source Adapters
   │    └─ 将不同来源统一为标准候选格式
   ├─ Candidate Normalizer
   │    └─ 清洗、分类和去重
   ├─ Evidence Ranker
   │    └─ 按相关性、时效性和证据质量排序
   └─ Gameplay Analyst
        └─ 深入分析排名靠前的 3–5 个案例
```

执行顺序：

```text
生成 Search Brief
→ 并行检索白名单来源
→ 标准化结果
→ 按 URL、素材指纹和语义去重
→ 初步相关性与证据排序
→ 深度分析前 3–5 个候选
→ 生成行业总结
→ 流式返回结果
```

排序策略必须具有显式版本，以便回溯结果和后续评估。

## 8. 数据持久化

保存三类独立业务记录：

- **Research Run**：Search Brief、状态、来源范围、开始和结束时间、策略版本、缓存信息以及脱敏失败分类。
- **Research Candidate**：归一化候选、来源、证据、指标类型、玩法分析、置信度和必要快照元数据。
- **Reference Selection**：主参考、附加亮点、调整要求、排除项及采用时间。

相同品类、地区、平台、时间范围和搜索策略版本的有效结果可以复用。缓存结果必须展示其生成时间；过期策略由具体来源和业务要求配置。

## 9. 对话内交互

所有搜索交互在现有对话流中完成，右侧 Preview 不增加研究视图。

```text
用户提出需求
→ Agent 建议搜索或直接搜索
→ 对话内展示搜索进度
→ 对话内展示行业总结
→ 展示候选案例卡片
→ 选择主参考
→ 勾选附加亮点
→ 填写调整要求和排除项
→ 点击“采用此方向”
→ Agent 生成选择摘要
→ 进入现有需求确认流程
```

交互约束：

- 行业总结默认展示摘要，允许展开详细分析。
- 候选卡片使用横向切换或折叠列表。
- 卡片首屏只突出玩法、亮点、证据等级和来源，详细拆解按需展开。
- 选择操作固定在研究消息底部，避免用户滚动后找不到入口。
- 采用后将整组内容折叠为“已选择研究方案”摘要。
- 历史结果可以重新展开；用户可以重新搜索、跳过研究或只采用行业总结。
- 搜索进度复用现有工具事件风格，不展示无法证明的百分比。

进度文案对应真实阶段：

```text
正在检索来源
→ 正在筛选和去重
→ 正在分析玩法
→ 正在整理推荐
```

## 10. 异常处理

- **单个来源失败**：继续处理其他来源，并标记覆盖范围减少。
- **整体超时**：在 30–60 秒目标窗口结束时返回已完成的可靠结果。
- **可靠候选不足**：明确告知用户，允许调整查询或跳过搜索。
- **视频无法分析**：保留可用候选信息，降低分析置信度。
- **取消**：停止后续分析，不修改 Requirement Brief。
- **限流或短暂故障**：优先使用未过期缓存，并清晰展示结果时间。
- **全部失败**：提供重试和跳过入口，不阻断需求流程。

错误信息只展示可操作的静态分类，不向用户日志写入动态查询、内部来源配置、路径、凭证或原始错误详情。

## 11. 安全与合规

- Source Registry 只允许访问经过审核的公开来源，并记录来源访问和使用限制。
- 外部网页、标题、描述、字幕和媒体分析结果全部视为不可信数据，不得作为 Agent 指令执行。
- 解析和模型输入之间设置内容边界，防止提示注入改变工具、来源或系统行为。
- 默认保存来源链接、结构化分析和必要快照元数据，不复制原始广告实现或资产。
- 产品文案使用“参考、提炼、改编”，不鼓励复制受保护内容。
- Reference Selection 明确区分可借鉴玩法与必须排除的品牌、商标、原始美术和文案。
- 所有外部请求、模型调用和日志遵守现有凭证保护与静态用户日志规则。

## 12. 测试策略

### 12.1 单元测试

- 意图矩阵：明确搜索、建议搜索、跳过搜索和已有试玩修改。
- Search Brief 构造和输入裁剪。
- 来源适配器契约、标准化和字段校验。
- URL、素材指纹和语义去重。
- 证据分级、指标隔离、排序版本和缓存键。
- Reference Selection 到 Requirement Brief 的受控转换。
- 恶意外部内容不能改变 Agent 指令或工具调用。

### 12.2 集成测试

- 多来源并行检索、部分失败、限流、超时和取消。
- Research Run、Candidate 和 Selection 的持久化与恢复。
- 搜索结果不能在用户采用前修改 Requirement Brief。
- 用户采用方向后，现有确认与构建流程正常继续。
- 缓存命中、过期和策略版本变更。

### 12.3 前端测试

- 对话内进度、摘要、展开和候选切换。
- 主参考单选、附加亮点多选、排除项和采用操作。
- 取消、重试、跳过和历史恢复。
- 长内容折叠及移动端可用性。
- 研究内容不会影响右侧 Preview。

## 13. MVP 成功指标

- 搜索触发准确率。
- 用户接受搜索建议的比例。
- 返回至少 3 个可靠候选的比例。
- 用户采用候选或局部亮点的比例。
- 搜索完成时间的 P50 和 P95。
- 每个结论具有来源和证据等级的完整率。
- 搜索后进入 Confirmation 的转化率。

所有指标必须区分“直接搜索”和“Agent 建议后搜索”，以评估意图识别和建议策略是否有效。

## 14. 后续演进

1. 接入自有投放指标，按权限展示 CTR、CVR、IPM 和 ROAS。
2. 接入第三方广告情报平台，并明确其估算属性。
3. 建立内部优秀案例库、人工标签和审核流程。
4. 增加内容哈希、相似创意聚类和跨任务结果复用。
5. 当研究维度和数据量明显超过对话卡片承载能力时，再评估独立研究工作台。
